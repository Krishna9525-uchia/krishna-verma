## 2025-12-04 - Form Label Association & Affordance in Dynamic Interactive Forms
**Learning:** In dynamically generated calculator interfaces (where inputs/selects are mapped from database-like schemas), form labels often get rendered as simple static text without semantic target associations. Adding the `htmlFor` and corresponding input `id` attributes (using the stable field name `inp.name` as the identifier) restores proper screen reader focus and accessibility tree hierarchy. Coupling this with the `cursor-pointer` class on the labels provides immediate visual hit-target affordance for mouse and touch users, making the entire label area interactive.
**Action:** Always map stable configuration keys (e.g., `inp.name`) to `htmlFor` and `id` when rendering mapped form fields. Ensure labels are explicitly styled with `cursor-pointer` to improve both a11y focus and tactile usability.
